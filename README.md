# AutoTest 业务测试平台

单机工作台使用 Vue 3、shadcn-vue、NestJS 和 SQLite。TesterArmy/e2e 0.23.0 与 Web Engine 0.15.5 通过 pnpm workspace 安装。实施依据为上级目录的《TesterArmy_e2e_AI测试平台_实施方案_单机版.md》。

## 在终端独立启动

使用 Node.js 24.8 或更新版本和 pnpm 12.11.2，在本目录执行。

```powershell
pnpm install --frozen-lockfile
pnpm db:setup
pnpm build
pnpm start
```

在普通终端执行上述命令。使用已有数据库时可跳过首次初始化 `pnpm db:setup`。构建完成后，日常只需运行 `pnpm start`，打开 [工作台](http://127.0.0.1:3211/)。同一个进程提供前端和 API。端口可通过 `PORT` 修改。开发时可使用 `pnpm dev`，开发前端在 [5175 端口](http://127.0.0.1:5175/)。

已有数据库升级时，先关闭正在运行的 API，再执行 `pnpm --filter @autotest/api exec prisma db push` 同步数据库并生成 Prisma 客户端，然后重新启动。

「测试用例」中的 **TC-DEMO** 可以直接执行。它打开内置任务页，为移动节点配置校验 Hook，保存后重新打开页面验证两个字段。首次运行缺少 Chromium 时，Web Engine 会自动下载，也可以先执行 `pnpm browser:install`。

## 测试准备

在「设置」中选定测试站点。「测试准备」可以独立运行服务同步、地图绑定和就绪复核，使用目标站点已有的服务与地图。

1. 实施同事在「测试准备 → 流程与规则」选择 Paladin 服务识别方式，保存规则版本。在步骤列表中组合准备流程并指定规则版本。已有流程可以另存，历史运行保留原版本。
2. 测试同事在「运行准备」中选择流程，填写目标地图全名。显式指定模式还需服务全名。仅同步服务的流程可直接运行。
3. 首次使用新规则时试跑完整流程。通过最终复核后，规则会标记为已验证。「运行记录」可查绑定前后的地图、服务同步结果，并可复制交接清单。用同样参数再次运行会复用已有绑定。

升级已有安装时，按上节的数据库升级步骤添加准备流程、规则和运行记录表。

## 从需求生成并发布

1. 在「设置」填写模型接口基地址、模型名称和 API Key。接口应兼容 OpenAI Chat Completions，并支持工具调用。Temperature 和最大输出 Token 可选，保存后立即生效。设置页填写的 API Key 明文存入本机 SQLite。已有 `apps/api/.env` 配置可作默认值。
2. 在「设置」选用目标测试站点。进入「AI 创建」，选择默认业务 Skill 或使用自动匹配。描述目标、必要参数和预期，生成计划后确认并保存。跨模块用例可给各步骤选择不同的业务 Skill。需要沿用前一步的设备或任务时，在相关步骤中写明同一个唯一标识。
3. 在用例页点「AI 生成脚本」，确认测试目标、动作和断言，再点「开始探索」。复杂操作可以由 `agent.act` 完成，断言由确定性定位器执行。
4. 勾选失败修复后，平台可对定位、操作和页面状态等待失败自动修复，最多两轮。对于旧版任务配置脚本，如果按“回调”文字检查执行图失败，但现场能将回调卡片的实际标识与图节点对应，平台可将保存前和回读后的两处定位一起修复并试跑。缺少证据或实际业务结果不符时会保留失败。若正数计数断言匹配了过多元素，可在失败详情手动发起修复。AI 根据证据从业务 Skill 中选择更窄的定位，原期望数量和其他断言保持不变。修复版本会重新试跑，结果可从原运行进入查看。当前版本已有通过记录时，历史失败页会显示对应链接。平台会跳过近期在同一环境已失败的相同流程。若修复试跑在更早的业务步骤失败，平台将停止自动修复，并在该修复版本仍为当前草稿时恢复原版本。
5. 确定性脚本可在首次执行通过时完成零 AI 验证。含 Agent 动作的脚本探索通过后通常会追加严格回放。任务配置用例若先查重再新增固定名称，且结束时记录仍存在，探索详情会提示准备测资后手动验证。修复验证通过后，可复用的操作和计数定位会写入业务 Skill 的 `references/verified-repairs/`。验证通过后可发布，后续默认运行严格回放。已发布的旧版本可在版本历史中查看。

「设置 → AI 模型」中的「脚本生成推理模式」默认开启官方 DeepSeek Flash 和 Pro 的高强度推理。可手动选择关闭、低、高、最高，或沿用服务商默认。其他兼容接口使用各自的服务商默认模式。脚本生成超时默认 120 秒，可设为 30 至 300 秒。推理模式和此超时只应用于生成脚本。

任务测试可选择「服务同步与地图绑定」前置 Skill，填写地图完整名称。存在多个 Paladin 服务且尚未绑定该地图时，填写目标服务的完整名称。保存后生成脚本，运行会先验证所有条目已同步且目标地图已绑定，前置条件失败时可在运行详情查看原因。

## 业务知识和测试环境

业务 Skill 位于 `skills/<目录>/SKILL.md`。工作台支持维护 Skill 文件。生成时加载所选 Skill、该目录下的 `schema.json` 和 `references/`。内置 Skill 涵盖任务流程、Hook 配置、设备配置、项目管理以及失败诊断。

接入真实系统时，为可测试控件提供稳定的 `data-testid`，并将页面路径、字段、枚举和定位信息写入对应 Skill 的 Schema。可设置 `BUSINESS_CONTEXT_BASE_URL`，创建用例时填写任务 ID。平台用只读 `GET <基地址>/tasks/<任务 ID>` 拉取任务图、节点、Hook Schema 和已有配置，供规划与脚本生成使用。接口应返回脱敏 JSON，耗时上限 8 秒。

测试站点的账号和密码可在「设置」明文保存。在用例需求中写明登录路径、已知输入框定位和成功判据，并注明使用设置中的测试账号。Runner 执行登录步骤时读取当前配置，密码通过 e2e 的凭据接口填入。

当前内置任务页用于本地演示，配置保存在独立浏览器会话的本地存储。真实任务系统的 Canvas 节点定位、业务 API 字段映射及仿真行为需要按目标系统接入和验证。

## 回放与本地资产

- `storage/app.db` 保存用例、版本、排队状态和运行记录。
- `e2e-project/tests/generated/` 保存按版本生成的脚本。版本发布时校验源码、依赖锁文件、运行配置、测试站点和缓存的指纹。
- `storage/replay/` 按用例、版本和环境分开存储 TesterArmy Replay Cache。
- `storage/artifacts/run-<ID>/` 保存执行日志、e2e JSON 报告、Trace 和截图等实际产物。

严格回放使用 `--strict-cache` 和只读缓存，子进程只继承必要的系统变量。e2e 0.23.0 获取 Agent fixture 时要求模型对象，因此平台提供无凭据、无网络实现的离线对象。任何推理尝试立即失败。只有实际断言通过、所有 Agent 步骤完整命中缓存且报告模型调用数为 0，版本才能通过验证。缓存丢失、脚本变动或环境变化会触发重新验证。

零 AI 回放仍会打开真实站点并执行用例中的保存和修改。固定名称的新增用例需要每次从满足查重条件的测资开始。比如 TC-007 成功后会留下 `legoTask2`，再次运行前需在隔离环境准备测资或恢复到新增前的状态。同名记录会在新增前拦截。迁移已有工作台时需一并保留 `storage/app.db`、已生成脚本、回放缓存和业务 Skill。

含 Agent 步骤的探索以「设置」中的运行超时作为 e2e 用例执行上限。达到上限后，执行器预留最多 30 秒供子进程结束并归档报告。运行详情优先显示用例超时原因。

构建验证命令为 `pnpm typecheck` 和 `pnpm build`。执行与缓存细节见 [TesterArmy/e2e 缓存文档](https://e2e.com/docs/cache)。
