# 任务流程测试

## 业务概念

- 任务由流程图编排，节点之间存在连线与分支，同名节点（如多个“移动节点”）可能大量出现。
- 节点具有生命周期阶段（如“创建时”“离开前”），Hook 绑定到具体生命周期。
- 任务图是实时数据，**不要**把节点列表、字段选项硬编码进用例；执行时通过业务 API 获取。
- 目标节点定位优先级：节点 ID（nodeId）> 业务属性组合 > 拓扑条件；禁止“第 N 个同名节点”式定位。

## 测试生成步骤

1. 通过只读 API 读取任务图，确定唯一 nodeId 与节点类型。
2. 获取节点 Schema，校验需求中的字段、枚举合法性。
3. 形成业务步骤与预期结果（动作单一、可验证）。
4. 使用 e2e 在真实界面操作，不得直接修改前端状态代替 UI 测试。
5. 保存后必须验证：UI 提示 + 重新加载页面 + 只读 API 持久化三层一致。

## 检查点清单

- 任务图加载完成（节点数量、连线渲染）。
- 选中节点后右侧属性面板与节点数据一致。
- 保存成功提示 ≠ 配置保存成功，必须重新加载验证。
- 分支/缩放/滚动后的画布操作可重现。
