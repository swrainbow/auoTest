# 服务同步与地图绑定

独立准备基础数据时，在「测试准备 → 流程与规则」维护服务选择规则和步骤顺序。运行参数使用测试站点中已有地图的完整名称。“自动确定”先采用运行人填写的服务全名；省略时，选择唯一候选或唯一已绑定该地图的候选。“每次填写服务全名”将服务名设为必填。新规则通过完整流程的最终回读后可在记录中看到验证状态。

在业务用例中选择此前置项时，沿用自动确定服务的方式，在同一浏览器会话中先完成准备，再执行业务步骤。

1. 从左侧「配置」进入「服务管理」，页面路径为 `/config/tuskService`。需要登录时使用平台设置中的测试账号。
2. 逐条读取「同步状态」。已成功的条目继续检查下一条。已在「同步中」的条目按编号轮询至完成。需要发起同步的条目，点击该行「同步」并确认一次，再按编号回读本次同步时间和后台状态。遇到明确失败或等待超时，记录该服务名称、同步时间、最后状态和可见的失败原因。
3. 找到名称以 `paladin` 开头的服务。若对应条目的「地图」已包含完整名称完全匹配的地图，保留当前配置。否则点击该行「修改」，在「修改服务」弹窗找到地图多选框（本次站点显示为「地图」）。收起时在该字段的 combobox 按 ArrowDown，等展开后在它关联的列表中选中目标全名。已有标签的关闭按钮可能位于多选框中央。核对原地图和新地图都已选中，按 Escape 收起，点击「确定」，再从同一服务行的「地图」列验证绑定结果。
4. 每次新增绑定并保存后，在刚才的 Paladin 和对应的 Rattletrap 两行分别点击「同步」，按提示确认。即使当前两行均显示「同步成功」，也要在保存后重新发起。按服务全名回读两行同步结果及 Paladin 的地图绑定。需要对已有绑定补做这一步时可单独使用[地图绑定后同步](../tusk-map-binding-sync/SKILL.md)。
5. 完整准备流程最终复核所有服务的同步状态。地图缺失、服务归属不明确或同步失败时，记录有关服务全名和实际状态。
