# 地图绑定后同步 Paladin 和 Rattletrap

1. 进入「配置 → 服务管理」（`/config/tuskService`）。从本次绑定结果取得地图全名、Paladin 服务全名。单独补同步时，在该 Paladin 行的「地图」列核对目标地图已绑定。
2. 定位本次 Paladin 和对应的 Rattletrap 两行。优先按指定的服务全名和类型定位。站点只有一个 Rattletrap 时使用该服务；有多个候选且缺少对应关系时，列出候选并取得目标服务全名。Rattletrap 的「地图」列可能显示为「--」。
3. 保存绑定后，分别处理目标 Paladin 和 Rattletrap。记下服务编号和列表中的同步时间，在目标行点击一次「同步」并确认。提交成功只表明后台已受理。对于已经发起的本次同步，若列表显示「同步中」，继续回读该服务。
4. 从服务管理页重新获取的列表中按同一编号检查同步时间和状态。本次提交后的同步时间已更新、状态达到「同步成功」时，该服务完成。两个服务均完成后，再核对 Paladin 的原地图及目标地图。若后台明确拒绝或返回失败，记录服务名、后台原因和最后状态。等待超时时记录最后状态及同步时间；续跑先查这次同步是否已经完成或仍在执行。

## AutoTest 调用

执行器每次回读后间隔约 2 秒再查，每轮同步最多等待 120 秒。若在保存新绑定时已有旧任务执行，先等旧任务结束，再为新绑定发起同步。

- 需要**追加绑定并同步**时，在同一个业务步骤使用 `bind-paladin-map`。本次新增绑定后，该动作包含两个服务各自的同步与回读。若用例要求每次执行都同步两个服务（包括地图已经绑定时），在此操作上设置 `syncExisting: true`。
- 地图已绑定、需要**单独补同步**时，使用 `sync-bound-map-services`。如果上次地图已保存但同步失败，从这个动作续跑，它会按本次要求重新同步两行。以下示例中的地图和服务名均取本次输入。

```json
{"type":"sync-bound-map-services","mapName":"Task002","serviceName":"paladin-1","rattletrapName":"rattletrap"}
```

两种动作都接受可选的 `serviceName` 和 `rattletrapName`。使用已登录的服务管理页面；新会话需要登录时，使用平台配置的 target 凭据。同步动作内会按行回读结果，用例可在 checks 中按实际服务全名分别核对两行「同步成功」。
