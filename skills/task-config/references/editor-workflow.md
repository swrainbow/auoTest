# 任务配置编辑流程

依据目标测试环境的操作证据及 [V5.9 手册页面操作](https://doc.tuskrobots.icu/share/n8lwOSbBZH7SlGhT_1794972906676.html#页面操作) 整理。下方已核实定位用于自动化。手册配图中的标签和布局用于确定操作意图，实际默认值与可用控件按目标环境读取。

## 测试环境已核实的定位

- 首次进入任务配置使用 `{"type":"open","path":"/task/taskLego"}` 后紧跟 `{"type":"ensure-task-config-session"}`。启动画面「即将开启，请耐心等待」结束后，只有账号、密码和登录按钮都就绪才提交登录；已有会话时直接等待任务列表。不重复填写账号或密码。右上角的许可证「警告」是通知，许可证有效时无需操作通知即可登录。超时后查看启动、网络及许可证状态。
- 列表使用 `.el-table__body`。新增使用角色 `button`、名称 `添加`。编辑器使用角色 `dialog`、名称 `任务配置`。外层保存按钮的名称是 `确定`，可用 `[role="dialog"][aria-label="任务配置"] button[name="确定"]` 限定范围。保存后可验证编辑器隐藏。
- 从列表回读时，先用 `filter-task-config` 按完整名称筛选并确认唯一行，再执行 `{"type":"press","locator":{"kind":"css","value":".el-table__body tr:has(td :text-is(\"完整名称\")) button[title=\"修改\"]"},"key":"Enter"}` 打开该行编辑器。右上角许可证或保存通知可能遮住该按钮的鼠标点击区域。
- 主流程画布用 `.vue-flow:has(.vue-flow__node-llm)` 定位，主节点标题位于 `.node-header > div`。主流程连线用 `.vue-flow:has(.vue-flow__node-llm) .vue-flow__edge` 计数。阶段抽屉的「执行顺序」使用另一个 Vue Flow 画布，两张图的边可能有相同的 `data-id`。在各自画布内核对连线，并在来源、目标可确认时核对连接方向。默认主流程有两个主节点和一条从 `取货` 指向 `放货` 的连线。用 `.vue-flow__node-llm:has(.node-header > div:text-is("移动"))` 查找移动主节点。
- 全局配置的齿轮是 `.vue-flow__controls-button.control-icon`。名称输入框可用 `.el-drawer:visible input[placeholder="请输入名称"]`，应在全局配置面板打开期间断言其值。需要在后续编辑前返回画布时，可以先做名称断言，再在下一步关闭面板。时态阶段在对应主节点的 `.node-item` 中，显示 `创建时` 或 `离开前`。
- 在当前测试环境，「容器类型」的标签是 `.tk-form-dynamic-item-label-text[data-field="containerType"]`。在「全局配置」抽屉内定位该标签所在的 `.tk-form-dynamic-item`，读取 `.el-select__placeholder` 的选中值。此环境的「全局配置」未显示「机器人分组」。只核对页面实际提供的默认字段。与旧定位对应的规则在 [locator-repairs.json](locator-repairs.json)。
- 返回画布时，点击对应抽屉的关闭按钮。全局配置使用 `.el-drawer:visible:has(.el-drawer__title:text-is("全局配置")) .el-drawer__close-btn`。在操作序列中等待该抽屉隐藏，再确认「任务配置」对话框仍可见，随后操作画布。如果关闭按钮点击成功但抽屉仍在，保留现场并排查名称字段提交、表单校验和抽屉状态。按 `Escape` 可能连外层编辑器一起关闭。
- 在「取货」后插入「移动」时，点击 `.vue-flow__node-llm:has(.node-header > div:text-is("取货")) .node-header > div:text-is("取货")`，再点同一节点内的 `button.common-node-add.position-bottom`，最后点 `li.tusk-menu-item:visible:text-is("移动")`。插入后核对三个主节点及两条连线。
- 删除主节点时，在该节点范围内点击 `.node-header .el-dropdown:last-child button` 打开菜单，再点击精确名称为「删除」的 `menuitem`。每个待删节点分别打开自己的菜单，最后核对剩余节点和连线。定位菜单时避开列表工具栏上同名的「删除」按钮。
- 新增时态阶段使用 `{"type":"add-task-config-stage","node":"取货","stage":"离开后"}`。在唯一的目标主节点内打开标题右侧「+」对应的阶段菜单，确认菜单展开后选择完整阶段名。单独断言该阶段出现在此节点的 `.node-item` 中。若同一画布有多个同标题主节点，先用图中的节点标识区分。
- 修复阶段菜单超时时，保留结构化的新增阶段操作和节点内断言。标题区同时有阶段菜单和节点操作菜单，`button:first-of-type` 可匹配两个按钮。按触发器的 `aria-controls` 找到含目标阶段的菜单，在对应触发器上按 ArrowDown。等该菜单内完整同名的菜单项可见，在菜单项上按 Enter，再回读目标节点的阶段。已在「取货 → 离开后」的未保存草稿中核验此操作。
- 打开指定时态阶段时，在对应主节点内点击 `.node-item > div:text-is("创建时")` 或对应阶段名称。各 Hook 由抽屉内的 `.tk-form-switcher-section` 包裹，使用标题后缀定位，例如 `:has-text(" - 校验")`。
- 校验、后处理、回调的 Element Plus 下拉统一使用 `select-element-plus`。例如「校验 → 货物状态」使用 `.el-drawer:visible .tk-form-switcher-section:has-text(" - 校验") .tk-form-dynamic-item:has-text("货物状态") .el-select` 作为 `selector`，`value` 为 `不校验`。回调请求方式使用同一 Hook 内 `.el-input-group__prepend .el-select`，阻塞方式使用 `.tk-form-dynamic-item:has-text("阻塞方式") .el-select`。由平台打开外层控件，读取输入的 `aria-controls`，在对应列表里按精确选项名称点击，再用字段内的 `.el-select__placeholder` 核对选中值。不同字段可同时保留同名列表项。
- 在「离开前」抽屉添加回调时，先记录现有 Hook，再点击 `.el-drawer:visible .tk-form-switcher-header-actions button`。Hook 选项在 tooltip 浮层中，使用 `screen.getByText("回调", { exact: true })`，在结构化操作中写 `{"type":"click","locator":{"kind":"text","value":"回调"}}`。主流程节点菜单的 `li.tusk-menu-item` 定位仅适用于主流程追加。后续操作限定在 `.tk-form-switcher-section:has-text(" - 回调")` 内。
- 核对回调添加前后的 Hook 集合时，按「机器人」「后处理」「回调」分别定位并检查数量，再核对各自字段。集合定位用数量断言。
- 回调地址使用 `.el-input-group--prepend input.el-input__inner`。按用例原样填入地址，包括明确要求保留的占位文本，再按 Tab 提交输入。方法文本位于 `.el-input-group__prepend .el-select__placeholder`，阻塞方式文本位于 `.tk-form-dynamic-item:has-text("阻塞方式") .el-select__placeholder`。保存前核对具体值。保存并从列表重新打开同一模板后，在同一主节点和时态阶段回读地址、方法、阻塞方式和已有 Hook。
- 核对请求和回复参数时，点击回调地址右边的圆形「…」（回调 Hook 内的 `button.is-circle`）。实际内容在打开后的 `.node-detail-dialog:visible` 里，两个 `.cm-content` 编辑器依次对应「请求配置」和「回复配置」。若用例要求保持默认值，在保存前分别读取两份 JSON，重新打开后按字段、值及类型与保存前对比。用弹窗自己的 `button.el-dialog__headerbtn` 关闭详情。
- 保存前先关闭回调详情，再关闭对应阶段抽屉。外层确认后等待「任务配置」隐藏，通过重新筛选和回读验证保存；保存通知可能很快消失。
- 回读完成后，依次关闭详情和阶段抽屉，再按按钮角色及精确名称「取消」退出外层编辑器。不要假设操作按钮位于 `.el-dialog__footer` 内。
- 修改回调请求参数时，先核对两个编辑器的默认值。对 `:nth-match(.node-detail-dialog:visible .cm-content, 1)` 填入保留原字段的完整请求 JSON，再在该编辑器按 Tab。通过两个编辑器分别核对修改后的请求和原回复，保存后重新打开详情核对。保留业务指定的值类型，例如数字 `1` 与字符串 `"drop"`。

## 定位入口和控件

- 任务配置列表顶部的「添加」打开新增编辑器。「名称」列有筛选入口，目标行的「操作」列包含「修改」和「复制」。用完整名称确认唯一匹配，尤其是名称列有截断时。编号、屏幕行号及当前排序只能辅助查看。
- 名称筛选统一使用 `{"type":"filter-task-config","value":"完整名称"}`。该操作点击「名称」列筛选按钮，在含「请输入名称」的浮层内填写并提交，等待本次列表响应（目标环境为 `POST /prod-api/task/taskLego/data`）及页面分页总数刷新，然后通过同一筛选按钮收起浮层。用独立的精确行数断言判定同名配置是否存在。无匹配时页面显示「暂无数据」和「共 0 条」。筛选提交后浮层可能继续显示，勿用 `.el-popover:visible` 消失表示查询完成。
- 「任务配置」弹窗内，画布左上方的齿轮进入全局「设置」。主节点卡片标题包含动作名，右侧有 `+` 和 `⋮`；其下是「创建时」「到达时」「离开前」等时态阶段行，也有各自的操作菜单。先定位主节点，再在该节点范围内定位阶段。
- 画布下方工具条的 `+` 是缩放控件。主节点标题右侧的 `+` 用于添加时态阶段。新增主节点使用选中节点后在流程连接位置显示的添加入口。
- 阶段抽屉「Hook」标题旁的 `+` 添加 Hook。具体 Hook 卡片内的 `+` 用于添加该 Hook 的配置项，如「任务跳转」。阶段抽屉的「执行顺序」显示 Hook 关系。用实际卡片和该图中的 Hook 标识核对连线，确认编排后再保存外层模板。
- 阶段内有唯一回调、需要验证配置和回读时，在保存前使用 `{"type":"capture-hook-graph","node":"取货","stage":"离开后","hook":"回调","key":"afterLeaveHooks"}`。卡片标题显示「标识 - 类型」，图上显示标识。重新打开同一阶段，在抽屉关闭前使用相同参数的 `matches-hook-graph` 对比整张图的节点和有向连线。按实际用例填写主节点、阶段、Hook 类型和基线名称。

## 新增与调整主流程

1. 新增固定名称的配置前，按完整名称筛选。先确认筛选条件已提交、列表已返回新结果，再判断是否有精确同名记录：已刷新且为空的列表可用「暂无数据」和「共 0 条」确认；若刷新后的结果包含相似名称，再核对精确匹配。旧列表也可能没有目标名称，不能在提交后直接用精确匹配行数为 0 作放行条件。收不到查询完成的证据时停止新增；已有同名配置时记录测试数据冲突。通过检查后点击列表顶部「添加」，核对新流程初始主节点是否为「取货 → 放货」。进入画布左上方的齿轮「设置」，按用例填写名称，再返回画布。
2. 新增主节点时，点击作为插入位置的主节点标题，在它下方出现的流程添加入口选择动作类型，检查新节点的上游、下游和动作顺序。
3. 删除主节点时，在目标主节点卡片右上角打开 `⋮`，选择「删除」。检查剩余主节点的数量和连线顺序。
4. 按流程连线检查最终主动作序列。确认用例指定的名称与流程后，点击最外层「任务配置」弹窗的「确定」保存并退出。

## 修改已有模板或操作副本

1. 按完整名称筛选并确认唯一源配置。直接修改按目标行的「修改」进入。复制从源配置行点「复制」，V5.9 手册展示「复制任务配置」对话框，名称默认带 `_copy`。在对话框中核对来源和新名称，按用例修改并确认，保存后从实际副本行重新打开。若目标环境直接生成副本行，先读取实际副本名称，再进该行编辑。
2. 在画布中定位目标主节点，然后打开指定阶段。用例要求启用阶段时，先检查是否已存在，再按需通过主节点标题右侧的 `+` 添加。
3. 按用例定位目标配置项或回调条目。新增前核对已有条目，修改时按给定字段和值录入。用例指定顺序时，在「执行顺序」图核对依赖关系。
4. 完成内层编辑后，在最外层「任务配置」弹窗选择「确定」保存并退出，或选择「应用」保存并留在编辑器。「应用」已经提交本次配置，之后关闭编辑器也应按已保存状态回读。

## 其他列表操作

| 操作 | 配置和验证 |
| --- | --- |
| 重命名 | 目标行更多菜单选择「重命名」，检查新名称唯一，保存并刷新后确认旧名称不存在且新名称可回读原模板内容。名称变化也影响调用方的 `configId`。 |
| 删除 | 目标行更多菜单选择「删除」，核对二次确认对象。对用例指定的测试数据，按确认或取消分别核对目标行消失或仍存在。 |
| 批量修改 | 勾选目标行，用列表顶部「修改」打开「批量修改」。分组留空会清空所选模板分组，容器类型必填。回读目标行及未选对照行。 |
| 导出 | 点顶部「导出」，无名称筛选时检查全部模板，有筛选时检查 JSON 仅包含筛选结果。 |
| 导入 | 点顶部「导入」，选择同版本 JSON。存在同名模板时为导入项添加随机后缀，以实际名称回读，检查原模板仍存在。跨版本不可导入；文件成功导入后再核对参数与外部流程引用。 |

## 回读与运行验证

1. 回到列表，按本次保存的完整名称重新定位并打开模板。若通过「应用」保存，先退出编辑器，再从列表重新打开。
2. 保存回到 `/task/taskLego` 列表后，按上文的列表回读操作打开同一模板。只有用例明确要求验证浏览器刷新后仍然存在时才整页重载。新增流程核对名称、主节点数量和动作顺序。其他变更按用例核对节点、阶段、配置项、参数及执行顺序。
3. 副本探索结束后，将本次生成的副本交给已配置的 Runner 清理流程。尚未接入清理时，记录副本名称和待回收状态，避免把源配置或同名旧数据纳入回收。
4. 只有用例明确要求时才验证任务运行，按约定的运行条件观察结果。「到达时」是在到达目标点后执行该阶段的 Hook。「离开前」包含主动作及其后续编排。「进入前」「离开后」需先确认触发点位，再验证实际触发。
