# V5.9 进阶配置与验证

整理自 [V5.9 任务配置手册 · 进阶使用](https://doc.tuskrobots.icu/share/n8lwOSbBZH7SlGhT_1794972906676.html#进阶使用) 正文和配图。用例先确认系统参数、地图点位、接口契约和可观察结果。配置类用例保存后重开核对字段与执行图。运行类用例用测试任务的事件、回调记录和任务单验证实际行为。

## 回调字段与机器人动作参数

- 请求配置左侧键是发给第三方的字段名。值 `@字段名` 从 Lothar 默认回调字段取值，例如把 `@taskId` 映射到第三方任务号。无 `@` 的值原样透传。附属节点可用 `@mainPoint` 取主节点储位名（5.8 起支持）。联调时同时核对运行时替换值与字面值透传结果。
- 回复配置支持用 `==` 判断返回字段值是否相等。配图在 JSON `code` 上展示 `==200`。测试相等与不等两种回复，分别观察阻塞回调后的 Hook 是否开始；以回调配置中的业务字段作为判断依据，另记录 HTTP 响应状态。
- 工位、存储位、缓冲位的适用地图参数可进入任务的 `actionParameters`。机器人 Hook 的同用途配置优先于地图值。用两组数据验证仅设置地图时取地图值、二者同设时取 Hook 值。按当前机器人动作确认允许的参数与范围。

## 阻塞、并行与任务跳转

| 配置 | 运行行为与断言 |
| --- | --- |
| 回调或流程「阻塞」（默认） | 延迟成功回复，先确认依赖它的 Hook 尚未开始，再在回复成功后确认后续 Hook 启动。流程等待执行成功回复，回调等待符合配置的成功回复。 |
| 回调或流程「不阻塞」 | 保持外部回复未完成，观察后继 Hook 已按图开始，另记录外部动作最终结果。 |
| 同子任务 Hook 并行 | 在「执行顺序」图中将互不依赖的后继 Hook 挂在共同前驱下。保存重开核对分叉与前驱。运行时检查两条分支在依赖满足后可分别开始和完成。汇合和失败处理按当前项目契约设置断言。 |
| 「任务跳转」设为「是」 | 指定 Hook 完成后启动下一子任务，原先子任务的剩余 Hook 可继续执行。核对跳转触发时间、剩余 Hook 的事件和下一子任务的启动时间，分别观察机器人动作完成与 Lothar 任务单完成。 |

## 「继续任务」Hook 的接口名

运行到此 Hook 时默认等待第三方调用继续接口，也可在任务单强制完成该 Hook。正常联调按项目约定释放等待，逐项区分以下行为。

| 接口名 | 核对结果 |
| --- | --- |
| 继续任务 | 结束当前 Hook，同一子任务中配置的后续 Hook 继续执行。 |
| 追加任务 | 使用 `/rpc/task/continue`，传 `taskId` 与有序 `targets`。结束当前子任务，从任务尾部追加目标，使用 Hook 中选定的「任务配置」。接口另传 `configId` 时优先使用传入的配置。核对已有子任务与追加顺序。 |
| 完成任务 | 结束当前子任务，跳过其中剩余 Hook，有后续子任务时继续执行。核对当前子任务及下一子任务各自状态。 |

## 巷道、方向与区域选点

- 巷道多任务交换依赖系统参数 `4005`。`1` 按任务交换，由第三方管理库位。`0` 按库位状态交换，由 Lothar 管理库位。核对环境使用的管理方式与用例预期是否一致。
- 放货「进入前」回调 `/lothar/apply/switch` 对应交换目标点，巷道口需配置为途经点。绕圈回调使用 `/lothar/apply/circle`，巷道口途经点还需配置触发点位。分别核对阶段、地图依赖与回调路径。运行时根据回调和轨迹核对实际目标是否交换、机器人是否在巷道口绕行，接口参数和回复取当前项目契约。
- 双口巷道根据目标点所在区域的 `inboundTheta`、`outboundTheta` 选择进巷道放货、取货方向。配图在地图区域的「自定义配置」`customLothar` 中设置角度和选点模式。任务配置显式指定方向时优先。分别验证区域默认与模板覆盖，角度取测试地图数据。
- 区域与区域集合都支持选点模式，发任务使用区域名。`inboundMode` 用于区域放货，`outboundMode` 用于区域取货。`RESET` 每次从头查找；`INCREMENT` 记忆上一次选点；`RANDOM` 随机选点。固定区域可用点与起始状态后测试多次任务。随机模式核对目标属于可用集合，顺序与记忆模式按项目实际候选顺序断言。

## 接口用例与异常恢复

- **自动匹配模板**。系统参数 `6001`（图中 `device_points`）非空且创建任务未传 `configId` 时，将有序目标中列入 `6001` 的点用原名，其余用 `sto`，用连字符拼接模板名，例如 `sto-A-B`。测试三类输入，分别覆盖启用自动匹配、空参数、显式 `configId`；显式配置优先。拼接结果对应的模板需事先存在，未匹配时的回退按当前契约核对。
- **直接追加节点**。`POST /rpc/task/append` 接受 `taskId` 和 `taskTargets`，条目示例含 `action`、`target`、`wait`。尾部新增节点使用默认动作模板，相关回调在该默认模板配置。与 `/rpc/task/continue` 追加路径分别测试，核对追加顺序、实际动作及模板。完整动作枚举、`wait` 语义和默认模板映射需当前接口契约。
- **顺序与无序拣选**。`taskMode=orderPicking` 按 `targets` 中间点的下发顺序拣选，`disorderPicking` 由调度策略确定中间顺序。两种都先在起点取货，最后在终点放货。无序用例核对中间点的访问集合和起止动作；基线手册未给出完整高级接口协议。
- **目标点二次申请**。第三方端点示例为 `POST /applyNextTarget`，字段 `taskId`、`originTarget`。回调 Hook 的外层 URL 指向 Lothar，报文内 `url` 才指向第三方。配图是「移动 → 离开前」的阻塞回调，Lothar 路径在图中截断。配置前取得完整路径及回复契约，运行时核对原目标、回复目标和任务单实际目标。
- **按点位取消或继续**。有任务号时按任务号，之后才按点位查找。手册只给出 `/rpc/task/cancel` 的 `targetPoint` 请求截图，继续接口字段与同点多任务的处理范围取当前契约。在独立测试任务中断言本次目标任务结果及对照任务状态。
- **换车与子任务重做**。换车用于已取货机器人故障，容器已经转移到可重新取货的位置后，用任务单「换车」填写新取货点并验证接替机器人及后续任务。子任务重做针对已执行子任务，例如设备对接异常后重走进入申请；核对重做的子任务和是否重新发出了对应申请。恢复测试采用能观测设备状态的测试环境，并确认前置状态和目标子任务。
