# V5.9 经典案例与验收点

依据 [V5.9 任务配置手册「经典案例」](https://doc.tuskrobots.icu/share/n8lwOSbBZH7SlGhT_1794972906676.html#经典案例) 正文和配图。下面的配置验收都要保存后重开同一模板，核对主节点、选中的时态、Hook 参数和执行图。需要验证任务运行时，为配置回读和运行结果各写独立步骤，先确认测试地图和点位、设备流程或模拟回复、接口契约以及可观察的任务记录。模板名、容器、流程名、地址、设备信号、角度和点位采用本次测试的数据。

## 从提升机入到密集库

- 确认提升机进入申请、离开通知以及密集库巷道口的途经点和触发条件。核对系统参数 `4005` 对应的库位管理方，`1` 表示按任务交换，由第三方管理库位，`0` 表示按库位状态交换，由 Lothar 管理库位。
- 按序配置取货、放货主节点。取货启用「进入前」做进入申请，启用「离开后」做离开通知。放货「进入前」在移动之后执行阻塞的 `POST /lothar/apply/switch` 回调。回读时核对申请和通知条件、回调地址、巷道口配置，以及执行图中移动到交换回调的连线。路径来自手册区域章节，配图中的输入框仅显示了前半段。
- 在仿真或约定的设备联调环境中，按任务号检查进入申请获准后才进入提升机、通过离开触发点后才发离开通知，以及放货前交换发生并按约定顺序放到对应库位。需要证明顺序时，准备能产生交换的多个任务，同时核对任务记录和最终目标点。

## 拣选任务多段下发

- **创建后继续**时，在初始模板的最后主节点增加「继续任务」Hook，接口名选「追加任务」。图例放在末节点「离开前」。回读 Hook 位置和追加所用任务配置。运行时等任务进入等待状态，再向 `/rpc/task/continue` 传同一 `taskId` 和下一段 `targets`。核对等待被释放，新增段接在当前最后子任务之后，目标序列与 `targets` 一致。提供接口 `configId` 时，以接口参数选择模板。逐段核对原任务号、累计子任务和本次新增的顺序。
- **创建后直接追加子任务**时，按当前接口契约向 `POST /rpc/task/append` 提交同一 `taskId` 和 `taskTargets`。手册示例条目包含 `action`、`target`、`wait`，只展示了 `pick` 和 `false` 的组合。验证默认动作模板、追加节点的动作和目标、最终顺序。需要附带回调时，在对应默认模板配置并回读。完整动作枚举、等待语义和默认模板映射以现场接口为准。

## 提升机和输送线串联流程

- 库位取货后到提升机放货。放货「离开前」在主动作后接提升机取货流程，再接输送线流程。配图两个流程均设为「阻塞」，其中提升机取货的「任务跳转」为「是」。按现场流程名回读两张卡片和执行图。图中的 `lift-pick`、`lift-line` 是示例。
- 验证并行时，准备确实存在的下一子任务，并让测试输送线保持可观察的等待。核对提升机取货完成后才启动下一子任务，同一时间原子任务的输送线流程仍继续，随后按设备约定完成。记录子任务与 Hook 的状态或时间顺序，分别核验机器人动作结束与主任务完成。
- 「创建时」提前下发设备流程待确认。经典案例说明和配图均展示了这一操作，基础章节将「创建时」限制为校验和后处理。测试计划在取得目标环境的可选项及运行证据后再纳入此项。

## 缠膜机异常流程

- 任务模板负责正常链路，依次在库位取货、到缠膜机、等待缠膜完成、放到目的地。异常链路在「策略配置 → 触发」定义设备信号及执行回调，目标改为异常区。配图展示设备属性变化触发 `POST` 回调。异常接口、识别属性、状态变化、滤波次数和目标点由当前设备与项目契约提供。
- 正常信号下核对到达、等待完成、正常目的地和无异常回调记录。模拟异常信号后，按同一任务核对触发记录、异常回调和最终异常区，确认原正常目的地没有执行放货。设备的起始状态和目标点选择都用测试环境中可核对的数据。

## 机器人动作执行失败回调

- 使用 Lothar 基线的失败上报。到「配置 → 系统参数」检查测试环境的 `2008`（`action_failed_report`）为 `1`，以及接收端地址、基础路径和所需认证配置。配图的 `0` 是示例初态，手册正文的 `1` 是启用值。基线方案由系统参数生效，保持业务模板原有 Hook。
- 在可控仿真或测试环境中触发约定的机器人动作失败，对照任务和动作记录核验接收端收到失败消息，并核对消息属于动作失败类型。回调路径、请求字段、期望失败码以及重试次数以当前接口契约为准。只有保存回读证据时，验收结论只覆盖参数配置。
