# V5.9 模板和 Hook 规则

来源为 [V5.9 任务配置手册的功能介绍和配置说明](https://doc.tuskrobots.icu/share/n8lwOSbBZH7SlGhT_1794972906676.html#功能介绍)。此处记录手册行为、配置检查和运行预期。控件定位见 [编辑、保存和回读](editor-workflow.md)。

## 全局配置和主节点

先核对名称与容器类型，按业务指定机器人分组，再编排主节点、时态子节点、Hook 和依赖图。名称是创建任务用的唯一 `configId`。容器类型决定搬运对象，机器人分组决定可执行范围。分组为空时的调度范围需按目标环境确认。

| 主动作 | 运行时观察 |
| --- | --- |
| 取货 | 到目标附近后，在目标处取货。根据用例核对容器条码、货物状态和锁状态。 |
| 放货 | 到目标附近后，在目标处放货。根据用例核对最终放货目标和储位状态。 |
| 移动 | 到达目标点。可观察到点事件及随后触发的 Hook。 |
| 旋转 | 到目标后执行相对旋转。核对实际动作角度。 |
| 探测 | 到目标后扫描容器条码。比对场景需有任务容器条码和可观察的结果。 |

模板中的主、子节点保存的是结构。任务创建时提供与主节点数量相等的有序目标点，由此实例化阶段；阶段触发点由对应地图配置提供。任务涉及区域时以接口和区域选点规则为准。

## 五个阶段

一个主节点最多启用五个阶段，新增主节点默认启用「创建时」「离开前」。「离开前」及新增的移动阶段会生成相应的默认机器人 Hook。先读已有配置，再补充阶段和字段。

| 阶段 | 子任务及验证点 |
| --- | --- |
| 创建时 | 创建请求期间执行，不产生子任务。普通配置按手册基础规则只用校验、后处理。设备流程提前下发是[串联案例](classic-cases.md#提升机和输送线串联流程)中的个例，需核对当前版本是否支持执行。 |
| 进入前 | 有触发点才生效。机器人移到进入前触发点，再运行阶段 Hook。可检查设备许可是否发生在进入目标前。 |
| 到达时 | 生成到主节点目标的移动子任务。到位后执行此阶段 Hook，随后进入主动作。 |
| 离开前 | 生成主动作子任务，在目标点执行与主节点同类型的机器人动作，并按执行图执行后续 Hook。动作错配可能通过保存，但执行时报错。 |
| 离开后 | 常规顺序下，在离开前阶段 Hook 完成后移动至配置的离开后触发点，再执行 Hook。未设触发点时该阶段不生效。任务跳转场景另核对实际并发顺序。 |

「进入前」「到达时」「离开后」的标准机器人动作是默认移动，手册说明不可改为其他标准动作。需要确认机器人已经退出设备时，应观察离开后触发点及移动完成，单独验证放货或「离开前」状态不足以判断退出。

## 校验和后处理

校验只在创建时读取目标储位状态。货物状态可选「不校验」「有货」「无货」，锁定状态可选「不校验」「解锁」「锁定」。期望与实际不符时，验证创建失败和具体提示。后处理可在各阶段把货物设置为「有货」「无货」或「不处理」，把锁设置为「解锁」「锁定」或「不处理」。

| Lothar 管理储位的常见用例 | 创建时校验 | 创建时后处理 | 主动作后后处理 |
| --- | --- | --- | --- |
| 取货 | 有货、解锁 | 锁定 | 无货、解锁 |
| 放货 | 无货、解锁 | 锁定 | 有货、解锁 |

用执行顺序验证先校验再锁定、完成主动作再改货物状态或解锁。异常或取消时如何复原锁需另测。若由第三方管理储位，按需求核对「不校验」和「不处理」等约定。

## 机器人 Hook 参数

标准机器人 Hook 用于创建时以外的阶段。参数能保存时仍要核对适用动作，运行测试要查看最终下发或实际动作。

| 参数 | 适用动作与预期 |
| --- | --- |
| 取货前探测 | 取货。开启且任务带容器条码时，取货前扫码比对。 |
| 探测后比对 | 探测。开启且任务带容器条码时，探测后比对。页面也可能显示「探测后对比」。 |
| 旋转角度 | 旋转。表示到点后的相对转角。 |
| 停靠角度 | 全部标准动作。表示机器人到点的绝对角度。 |
| 容器停靠角度 | 放货、移动、旋转。表示负载容器的绝对角度。 |
| 重试次数 | 取货、放货。机器人切换为手动后恢复时重新计数。 |
| 提前上报完成 | 取货、放货、移动。核对完成信号与实际动作结束的时间，尤其是下游有交接依赖时。 |

「添加容器」「移除容器」是提升机放上或取走负载的附加动作，通常配在移动子节点。地图和模板同时提供参数时参照[进阶配置](advanced-config.md)核对最终值。

## 回调、流程、继续任务

| Hook | 需要配置与回读 |
| --- | --- |
| 回调 | 请求方法和 URL、请求映射、回复匹配条件、阻塞方式。JSON 回复 `code` 匹配规则和 HTTP 状态分别检查；阻塞模式等待业务成功回复，不阻塞在发送后继续。 |
| 流程 | 目标环境已配置的设备流程名称及阻塞方式。阻塞模式等待流程成功，不阻塞允许后续 Hook 提前启动。对应设备、信号和完成条件来自设备配置。 |
| 继续任务 | 设置「接口名」为继续任务、完成任务或追加任务。执行到这里会等待 `/rpc/task/continue` 或目标环境支持的人工完成操作。核对下表的后续路径。 |

| 接口名 | 调用后的运行验证 |
| --- | --- |
| 继续任务 | 当前 Hook 结束，同一子任务后续 Hook 继续。 |
| 完成任务 | 当前子任务结束，跳过它剩余 Hook，再继续后续子任务。事先核对是否会跳过必要的解锁或通知。 |
| 追加任务 | 当前子任务结束，在当前末尾追加新任务内容。使用请求的 `targets`，有请求 `configId` 时优先使用它，否则读取配置所选模板。 |

回调、流程和继续任务在普通模板按创建时以外的阶段配置。执行图要验证 Hook 的前驱和后继关系。任务跳转要验证指定 Hook 完成后下一子任务开始，同时原子任务后续 Hook 仍执行。设备许可、储位状态和后处理依赖按用例核对。
