# Lothar V5.9 任务配置测试

任务配置定义机器人任务模板，约束可执行的机器人分组和搬运的容器类型，并编排储位校验、状态变更、设备流程及 HTTP 回调。入口是「任务 → 任务配置」，路径 `/task/taskLego`。以 [V5.9 任务配置手册](https://doc.tuskrobots.icu/share/n8lwOSbBZH7SlGhT_1794972906676.html) 正文和配图为业务依据，以目标测试环境已核实的定位为自动化依据。

## 读哪份参考

- [模板和 Hook 规则](references/v59-template-and-hooks.md) 涵盖配置顺序、五种动作、五个阶段、六类 Hook，以及保存和运行中的关键约束。
- [编辑、保存和回读](references/editor-workflow.md) 涵盖从列表到画布的操作、已核实的定位、复制、重命名、删除、批量修改及导入导出。
- [进阶配置](references/advanced-config.md) 涵盖字段映射、动作参数优先级、并行、任务跳转、巷道、区域、任务接口和恢复场景。
- [经典案例](references/classic-cases.md) 给出五个案例及拣选的两种追加方式，按前置条件、配置回读和运行证据设计断言。

## 生成用例和脚本

1. 确认模板完整名称、是新增还是修改或复制、容器类型、机器人分组及有序主动作。名称用作创建任务的 `configId`。平台接入只读业务上下文时，可用「任务 ID」读取指定任务。定位已有模板时核对完整名称唯一命中；多个同动作主节点用已知节点 ID，或用流程序号、相邻节点和连线确定。
2. 按「全局配置 → 主节点 → 时态子节点 → Hook → 执行顺序」安排操作。对每个变更写明主节点、阶段、Hook 类型、字段值及前后依赖。已有目标阶段或 Hook 时，按用例修改已有条目。只填业务提供或目标环境已确认的流程名、点位、地址、参数和回复条件，待确认项写入计划的 `notes`。
3. 将进入编辑器、配置字段、保存和重新打开拆成可验证的步骤。回读时按用例核对模板名称和全局字段、主节点顺序和数量、启用阶段、Hook 类型与字段值、执行顺序图。使用已核实的 `data-testid`、精确角色/文本/占位符或 CSS。缺少可靠定位时，按平台规则使用 Agent 动作并跟上独立断言。
4. 需要运行验证时，明确测试环境、容器与机器人、初始储位状态、有序目标点、触发点、外部流程和回调契约。根据需求观察任务号下的子任务/Hook 次序、机器人动作、设备应答、储位状态及最终结果。保存回读和实际执行各有独立证据；手册案例中的名字、IP 和数值用于理解配置形态。
5. 涉及设备自身的配置，给对应步骤选用设备配置 Skill，任务模板的流程 Hook 引用已确认的流程名。任务运行依赖服务同步和地图绑定时，在用例的「前置操作 Skill」选择 [服务同步与地图绑定](../tusk-service-preflight/SKILL.md)，填写地图完整名称，已有前置结果可用于判定是否开始业务步骤。

## 生成前核对

- 模板阶段描述执行时机。一个主节点对应运行目标序列中的一个目标；「进入前」「离开后」生效另需各自触发点。
- 「到达时」先到目标再执行该阶段 Hook，「离开前」包含主动作且需要同动作的机器人 Hook。验证等待或设备交接时，以可观察事件确认放行边界。
- 校验读取储位，后处理变更储位。先明确由 Lothar 还是第三方管理储位，再决定是否校验、锁定、设置货物状态和解锁。
- 串并行以「执行顺序」图为准。回调或流程的阻塞方式、同阶段 Hook 并行、跨子任务的任务跳转分别核对。
- 导入导出文件内容、实际接口交互及设备信号需要对应测试工具或观测渠道。脚本只加入已确认能执行、能断言的操作，其余验证放入计划备注。
