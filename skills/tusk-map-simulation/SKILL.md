# 地图数据模拟

用户描述地图并要求导入时，一次完成布局设计、点线生成、JS 加密、点击上传和回读。给出原生整图包时直接导入。给出含 `mapDataList` 的明文整图并要求直接导入时，先编码再上传；若文件用作参考，则为新地图独立生成点码和线码。仅要求本地文件时，在要求的交付阶段结束。

## 在 AutoTest 中从描述运行

在「AI 创建」中使用此技能。以“生成二层 L 形地图，入口有充电位，末端有工位，中间设两个储位，导入到「二层取放货」”为例，模型按数量、位置和必达路线编排布局并固定到用例。登录选定的测试站点，打开 `/tkmap/mapDraw`。生成脚本时使用一次 `import-generated-map` 动作，将完整布局对象放入 `layout` 字段，结构见下方示例。动作会选中或新建指定名称的地图、生成明文、编码、点击整图导入控件、选择加密文件并回读。业务断言可另行核对地图名称。回放沿用该用例的布局。

按用户给出的地图全名查找，如 `Task001`。要求使用已有地图时，在动作顶层设置 `existingOnly: true`，缺图时停止。沿用该地图的实际楼层时省略 `layout.floor`，运行时按所选地图的 ID 回读楼层并填入明文；若需求明确限定楼层，则填入数值并在上传前核验。仅描述了形状并允许新建时，为新图取一个可辨认的模拟名称并填写楼层。需要登录时使用平台为目标站点配置的凭据。

**地图已创建、导入中断时**，续跑原用例的 `import-generated-map`，保留已确定的 `layout`、导入次数和业务断言。该动作会打开地图菜单、按全名选择目标，再按当前地图 ID 读取已保存的内容。回读为空图时继续上传原布局，拓扑一致时直接核验，已有不同内容时报告差异。地图名称已经出现只说明建图成功。

如果报告同时出现 `getById` 的 `STEP_NOT_AWAITED` 和同名菜单项点击超时，先查看该次点击的原始错误。菜单项曾经可见，移动鼠标时仍可能收起。共享地图操作用 `ArrowDown` 展开菜单，在完整名称匹配的可用项上按 `Enter`，等选图和详情监听都结束，再核对地图全名和本次读取的 ID。生成脚本时直接调用该动作。

## 导入已有地图

1. 取得用户指定的原生整图文件，确认可读、非空，并记下文件名。Tusk 导出的 `.json` 可能是不透明文本，保留原始字节。需要一份现成的测试文件时，可直接取[已编码的 7 点取放货样例](assets/pick-place.import.json)。它使用本机 Lothar 5.10 的默认地图口令，含 3 个通道点、2 个储位、1 个工位、1 个充电位和 6 条双向连接。
2. 在目标站点进入「地图 → 地图」（`/tkmap/mapDraw`）。当前 AutoTest 站点的地图控件位于 `iframe#hyjalIframe` 内。按完整名称切换到目标图；需要新建时填写地图名和楼层，默认楼层为 1。等地图加载完成，核对当前名称、ID 和点位数，加载中的空白画布不能证明是空图。
3. 整图导入要求目标图的点、线、区域均为空。若已有数据，先核对是否是上次成功导入的同一份地图；已匹配时复用。否则说明同名图含数据，取得新的目标名称或由用户指定其他空图。保留现有数据。
4. 在当前地图**名称控件**上打开操作菜单（已知 Hyjal 版本为右键），选择「导入 → 导入地图」，将原文件交给文件选择器。上传以当前地图 ID 为目标。「导入点位」「导入储位」分别用于局部数据。若当前自动化执行器不能操作文件选择器，记录待上传文件和目标图，交给支持文件选择的执行器或用户完成这一步。
5. 等待导入结果及地图刷新，重新打开同一张图。核对地图名、点位与连线，并用来源提供的数量、点位名称或代表性通路比对内容。原包不可读且没有来源清单时，记录实际观察到的点线及抽查结果。超时先回读再决定是否重试，避免重复提交。

## 生成小地图

1. 从需求提取地图名、楼层、各类点位数量、布局、单向或双向通行、必须可达的起终点。区分点位总数与储位数。只随机化用户留白的内容，例如主通道朝向、支路位置、各工位的排列。仅说“小型简单”时，可选单层、6～12 个点、直线主通道配短支路，默认双向通行。显式约束优先；数量与布局冲突时指出具体冲突。
2. 常规双向仓储图用 `warehouse` 描述布局。模型确定主通道形状、拐点和数量，生成器以固定间距排列通道、成排储位和工位，再连接相邻点。直通道用 `shape: "straight"`，L 形用 `"L"`。例如 TC-013 的导入动作如下，A5 为拐点，回放时保存展开后的坐标和连线。

   ```json
   { "type": "import-generated-map", "existingOnly": true, "layout": {
     "mapName": "Task001", "ver": "5.9",
     "warehouse": { "shape": "L", "aislePoints": 10, "turnAt": 5, "storageCount": 20, "workCount": 10, "chargeCount": 1 }
   } }
   ```

   当同一排纵深有多个储位时，这套布局从通道经内侧储位到达外侧储位。若工艺要求每个储位可独立进出，或需求指定了平行双通道、缓冲位、途径点、单行线和特定位置，使用显式布局。画平行双通道时，让每个横向支路在两条通道上分别设对齐的节点，然后从同一行接入储位与工位。需要增加通道节点时，遵守用户指定的总点数。

   显式布局的格式见[小型取放货地图](references/pick-place.layout.json)。`points` 的 `id` 是布局内稳定的代号，`x/y` 的单位是米。普通点 `normal=1`，充电位 `charge=10`（生成非空且唯一的 `chargerId`），工位 `work=40`，缓冲位 `buffer=41`，储位 `storage=42`，途径点 `waypoint=50`。每条 `links` 填 `from/to/bidirectional`，生成器写出两条 `mapLineList` 记录，`reverseLineCode` 互指，`nodeStart/nodeEnd` 对应点码。将必须可达的起终点列入 `routes`。
3. 加密前核对点位数量、类型和布局。默认道路只连接同行或同列的相邻点，交叉口共享一个节点。穿过第三个点、重叠线段、无节点交叉都会校验失败。用户明确要求斜路时，在显式布局中设 `"geometry": "free"`，仍需通过穿点和交叉检查。下面的命令同时检查点码、端点、连通性和指定行程。修正报错的点或线后再构建。

   ```powershell
   # 在本技能目录下运行，使用 Node.js 24.8 或更新版本
   node scripts/check-layout.mjs references/pick-place.layout.json
   node scripts/build-map.mjs references/pick-place.layout.json 8 pick-place.map.json
   ```

4. 第二条命令输出带 `ver`、点、线和区域数组的明文地图，并打印点码对应关系。根据目标版本或参考图填写布局的 `ver`（如用户提供的 5.9 样图使用 `"5.9"`），省略时为 `"5.10"`。`8` 是示例源地图 ID。5.10 导入时会以目标地图 ID 替换编号前缀，保留末五位。地图名和楼层由所选目标地图决定。

## 用后端方式编码

1. 自动导入动作和本地命令共用 JS 编码器。默认使用后端参考脚本的地图口令。站点有自定义口令时，通过运行进程的 `TUSK_MAP_KEY` 覆盖。需要单独生成文件时，在技能目录运行以下命令，各输出使用新文件路径。

   ```powershell
   node scripts/map-codec.mjs encode pick-place.map.json pick-place.import.json
   node scripts/map-codec.mjs decode pick-place.import.json pick-place.readback.json
   (Get-FileHash pick-place.map.json).Hash -eq (Get-FileHash pick-place.readback.json).Hash
   ```

2. 哈希应相同。编码失败时保留明文；解码失败时核对站点口令、格式版本与输入文件。只要求上传文件时交付 `*.import.json` 并注明「已编码，待站点验证」。要求上传查看时，按「导入已有地图」将该文件上传到目标空图。
3. 刷新并重开后，与明文比对点位类型、坐标、物理连接数和必达路线。按后缀或类型与坐标对应点位，再核对端点和通行方向。单向连接可能含禁用的反向记录，统计可通行方向时排除禁用记录。

## 交付结果

报告模式、地图名、楼层、各产物的用途与文件位置，以及实际完成的最后一步。上传后附目标站点、实际点线数和路线核对结果。若要复现随机结果，附上本次布局文件。
