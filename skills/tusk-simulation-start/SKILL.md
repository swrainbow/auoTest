# 开启仿真服务

使用本次指定的测试站点和已有地图全名。实例名称取地图全名。APR 默认**增加到 3 台**，用户另行指定时采用其目标数量。后续步骤始终沿用同一地图和实例编号。

### AutoTest 脚本生成

进入对应页面后，按业务步骤使用下列结构化操作与断言。将示例地图替换为本次目标，`key` 是脚本内跨步骤引用实例的名称，创建操作会记录运行时取得的实际编号。

| 业务步骤 | operations 中的动作 | checks 中的结果核验 |
| --- | --- | --- |
| 追加地图绑定并同步 | `{"type":"bind-paladin-map","mapName":"示例地图","serviceName":"paladin-1"}`，可通过 `rattletrapName` 指定对应服务全名。保存新绑定后，动作依次点击 Paladin 和 Rattletrap 的「同步」。 | 核对两行都同步成功，且 Paladin 保留原地图和新增地图。 |
| 创建仿真实例 | 进入 `/task/simConfig` 后执行 `{"type":"create-simulation-instance","mapName":"示例地图","key":"instance"}`。该动作会跨页查重，遇到重名即结束用例并报告「告警」。 | 新增成功后执行 `{"type":"simulation-created","mapName":"示例地图","key":"instance"}`。 |
| 设置设备数量 | `{"type":"configure-simulation-apr","mapName":"示例地图","key":"instance","count":3}` | `{"type":"simulation-apr","mapName":"示例地图","key":"instance","count":3}` |
| 开启目标实例 | `{"type":"start-simulation-instance","mapName":"示例地图","key":"instance"}` | `{"type":"simulation-running","mapName":"示例地图","key":"instance"}` |

单独回读 APR 数量时，用同一 `key` 的 `simulation-apr` 断言。它会按本次编号重新打开「设备配置」、读取已保存数量并关闭抽屉，运行中的实例则读取已保存的设备配置。单独回读运行状态时使用 `simulation-running`；要求重新进入页面时，先 open 同一路径。上面两种回读都可独立执行。

创建实例会在站点留下记录。含 Agent 的创建用例探索通过后，平台暂缓自动完整回放。需要确认业务结果时，按探索记录里的实例编号核对状态和 APR。首次执行、修复试跑和手动回放都遵循下方的重名规则。

服务管理列表使用 Element Plus 表格。对明确指定服务全名的用例，可用 `.el-table__body tr:has(td :text-is("paladin-1"))` 定位服务行，并核验行内完整地图名称。追加和刷新后保留原有绑定的检查由 bind-paladin-map 执行。

## 1. 在 Paladin 上绑定地图并同步两个服务

进入「配置 → 服务管理」（`/config/tuskService`）。按指定的服务全名定位 Paladin；未指定时，选择唯一的 Paladin 候选，或多个候选中唯一已绑定目标地图的服务。候选仍有歧义时，列出服务名称，请用户指定。

读取该服务行的「地图」列。需要追加时点击该行「修改」，进入「修改服务」里的地图多选框（界面标签为「地图」或「地图项目」）。用 ArrowDown 展开，追加目标全名，核对原地图仍已选中，按 Escape 收起并点击「确定」。

每次保存新绑定后，在对应 Paladin 和 Rattletrap 行分别点击一次「同步」并确认。「同步中」期间轮询该服务，等两行本次同步时间及「同步成功」状态都已回读，再核对原地图和目标地图并进入仿真配置。已有绑定若需补同步，使用[地图绑定后同步](../tusk-map-binding-sync/SKILL.md)。同一用例已完成此前置步骤时沿用其结果。

## 2. 创建前按实例名称查重

展开左侧「任务」，点击「仿真配置」，确认路径为 `/task/simConfig`。在点击「添加」前读取实例列表各页，按「实例名称」完整匹配本次要创建的名称。

**名称已存在时，本次用例以「告警」结束。** 任一页出现同名实例即适用，无论其绑定地图或运行状态。报告中列出匹配实例的编号、绑定地图和状态，跳过新增及后续的 APR 配置和开启。完整读取列表并确认名称可用后，才进入新增流程。列表读取失败或提交出错时，保留实际错误。

点击**页面顶部**「添加」，打开「添加仿真实例」。在「绑定地图」选中目标全名，再核对「实例名称」，必要时改为地图全名。切换地图可能自动改写名称。Naga 服务沿用页面当前值，用户指定时选其指定值。点击弹窗「确定」。在列表中按新增编号和两列全名识别新行并记下编号。保存响应不明时先与提交前列表比对，再决定是否重试。

用户要求开启已有实例或续跑时，沿用可唯一确定的目标行，从当前进度继续。若目标行已是「运行中」，直接进入第 4 节核验。出现多个同名同图候选且无法从新增记录或已知编号确定目标时，列出候选编号和状态，请用户指定。

## 3. 在目标行配置 APR

1. 核对编号，点击该行「设备配置」。等待右侧「设备配置」抽屉出现，滚动到表头含「物理属性」「APR」「数量」的设备表。上方「注册充电桩」属于另一项配置。
2. 在 APR 配置行读取「数量」。小于目标时，使用该行加号逐步增加，或在可编辑数量框中填入目标值。读取最终显示数值。例如从 1 增至 3，只增加 2 台。已经等于目标时保留现值。如果当前数量已超过用户要求“增加到”的值，先说明现值与目标的差异，再决定是否需要减少。
3. 缺少 APR 行时，使用**设备表上方**的「添加」，按表单可用选项建立所需 APR 配置。若有多种适用物理属性或多条 APR 行且无法确定目标，以用户指定的设备配置定位。截图中的编号、物理属性和充电桩编号均为示例。
4. 点击抽屉底部「确定」。等抽屉关闭，按同一编号重新打开「设备配置」，核对保存后的 APR 数量。回读完关闭抽屉，回到列表。

## 4. 开启并判断结果

目标实例已在运行时，回读其状态，记录“已在运行”。若还需核实保存的 APR 数量，按同一实例编号在仿真列表的新分页响应中核对 `deviceData` 的 APR 配置行及其 `devNum`。运行中行提供「设备管理」；若配置行无法唯一确定或数量缺失，记录实际情况。

目标实例等待开启时，先检查「绑定地图」完全相同的其他实例。若有其他编号正在运行，报告占用地图的实例编号与名称，在当前步骤结束，保留其运行状态。

对待开启的目标实例，只勾选该编号行左侧的复选框，确认顶部「开启」可用，点击一次。等待列表更新，必要时刷新「仿真配置」，再按编号、实例名称及绑定地图回读。**同一行的「状态」变为「运行中」才判定开启成功**；行内出现「设备管理」「任务配置」可辅助核对。到此结束，无需进入发任务流程。

若出现「仿真操作失败」或等待超时，先回读该编号的状态，再检查同地图是否被其他运行实例占用。保留页面原始提示与最后状态，只有在原因得到处理后再重试。交付时写明地图全名、Paladin 服务、实例编号、保存后读到的 APR 数量，以及最终状态。仅观察到“创建”或“结束”时，报告实际状态。
